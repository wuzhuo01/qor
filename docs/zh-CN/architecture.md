# 架构

本页描述 V1.0 运行时现在的行为。它不是路线图。

## 运行流程

```text
Task
→ Plan
→ Assignment
→ Execution
→ Artifact
→ Review
→ Synthesis
→ Decision
→ COMPLETED
```

决策要求动作时：

```text
Decision
→ Action
→ Permission / Risk / Approval
→ WorldWriter
→ Independent WorldReader
→ Verification
→ SETTLED
→ Human CIO Outcome
```

决定不再采取动作时，不走第二条路径即可完成。`EXECUTED` 不是 `SETTLED`。

## 按能力分配

规划器收到能力目录，返回一份点名能力、依赖和期望产物的计划。它不点名 Agent。分配再选择持有所需能力的候选人。

generic profile 里的治理能力是组织机制。它们带有必需权限，因此不在可规划工作列表里。调用方在配置中加入工作能力。QOR 不会为了让演示跑起来而发明这些能力。

## 人类责任

`AWAITING_HUMAN` 表示任务在等人。一条活跃责任可以绑到这个来源上。通知可以记下负责人有事要处理。创建或转移这条责任时可以产生通知。清除或完成它不会产生通知。投递失败不会回滚责任或来源。

`ESCALATED` 只有这个含义：

```text
AWAITING_HUMAN → ESCALATED → AWAITING_HUMAN
```

它不是一般的失败状态，也不会从其他任务状态进入。

`BLOCKED` 是异常停止。V1.0 契约不定义进入之后发生什么，也不暗示重试、恢复或自动升级。

## 可靠性模型

已经有的：

- 入口守卫在执行前按已保存的任务状态检查一次。
- 任务状态就是执行生命周期。没有单独的执行对象。
- `OPEN` 允许第一次执行。
- `READY` 且已有活动计划时，允许恢复该计划。

没有的，并且本页不把它们写成后续承诺：

- `execution_id`
- 重试
- 崩溃恢复
- 执行幂等
- 并发控制
- worker
- queue
- dispatcher

这是 V1.0 的可靠性契约。它不是一套完整的可靠性系统。

## 调度器与事件路由

到期的日程打开一个来源为 `SCHEDULE`、状态为 `OPEN` 的任务。匹配的事件打开一个来源为 `EVENT`、状态为 `OPEN` 的任务。

调度器和事件路由可以把任务创建为 `OPEN`。它们不会自动执行任务。它们不调用 `run_task`。路由已解决的事件不是执行触发器。

## 证据边界

在已说明的限制下，V1.0 核心已证明：调用方提供工作能力时的组织闭环，经独立核验直到 Human CIO 记录结果的动作路径，这条闭环的实际试用，调度器和事件路由创建任务，通知，入口守卫，责任闭合，升级契约，以及状态机和权限不变量。

尚未充分证明：与具体业务无关、由真实语言模型完成的规划。没有提供：通用的业务能力目录，以及公开的中性业务例子。

教训只做检索。系统不会自动记录权威结果。

## 历史枚举值

部分历史枚举值因 V1.0 兼容性仍保留。它们不定义 QOR 的产品领域，也不代表 QOR 提供对应的业务能力目录。
